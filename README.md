# ゲーム企画ノート

質問に順番に答えていくと、「どんなゲームを作りたいのか」をまとめた1ページの企画書ができるツールです。HTMLファイル1つで動き、ビルドやインストールは要りません。

## 使い方

1. `index.html` をブラウザで開く
2. 左のステップ（基本情報 → 一言コンセプト → 作りたい体験 → … → 次に作るもの）に沿って質問に答える
3. 右側のプレビューに企画書が組み上がる
4. 試作品を遊んでもらったら「検証日誌」に結果を記録する
5. 最後の「仕上げと書き出し」で抜けと食い違いをチェックし、Markdown／AIへの相談文つき／JSONバックアップ／印刷（PDF）／共有リンクで書き出す

入力内容はブラウザの localStorage に自動保存されます。別のブラウザや端末に移すときは、JSONバックアップを書き出して「バックアップから読み込む」に貼り付けてください。

## ステップ構成

| # | ステップ | 主な質問 |
|---|---|---|
| 1 | 基本情報 | タイトル、ジャンル（＋ジャンルの型）、プラットフォーム、プレイ時間、ターゲット、制作人数・期間 |
| 2 | 一言コンセプト | ハイコンセプト、フック、似ている作品との違い |
| 3 | 作りたい体験 | 感じてほしいこと、プレイヤーは何者になるか、楽しさの種類、忘れられない瞬間、作りたくない体験 |
| 4 | デザインピラー | 3〜4本の柱（沿うアイデア／反するアイデア）、優先順位 |
| 5 | ゲームループと操作 | コアループ、1回の流れ、長く遊ぶ理由、動詞、3C |
| 6 | 主要システム | システムごとの働き、成功・失敗の条件 |
| 7 | 世界観・雰囲気 | 舞台、テーマ、ビジュアル、音、参考作品、ムードボード |
| 8 | 方針とスコープ | 守る方針、今回入れないもの、アイデア置き場、未決定事項 |
| 9 | 次に作るもの | プロトタイプで確かめたい問い、作るもの |
| 10 | 検証日誌 | 試作品ごとの問い・判定・結果・プレイヤーの反応・次に変えること |
| 11 | 仕上げと書き出し | 抜けチェック、見直したい点、書き出し、印刷・PDF、共有リンク |

## 主な機能

- **ジャンル別の問い**：基本情報で「ジャンルの型」（ローグライト／パズル／アドベンチャー・ノベル／アクション／RPG／シミュレーション・経営／ストラテジー）を選ぶと、各ステップの最後にそのジャンルならではの問いが出ます。ジャンル欄の文字から型を提案します。
- **見直したい点（矛盾・スコープチェック）**：「短時間が狙いなのに1回が長い」「制作人数・期間に対して要素が多い」「物語が主役なのに物語を削っている」などを、決まったルールで調べて問いの形で出します。当てはまらない指摘は企画ごとに非表示にできます。
- **検証日誌**：「次に変えること」は、ボタンで「次に作るもの」「未決定事項」に送れます。
- **ムードボード**：画像・音楽・動画・ページのURL、または手元の画像（縮小してブラウザーに保存）に「何を参考にしたいか」を添えます。
- **別案と比較**：「別案を作る」で企画を複製し、「比較」でコンセプト・ピラー・コアループなどを並べて違いを確かめます。採用／保留／不採用と、その理由を残せます。
- **印刷・PDF**：本文をA4・1ページ（3段組）に収めます。ムードボードと検証日誌は付録として2ページ目以降に入れられます。
- **読み取り専用の共有リンク**：企画を圧縮してURLの「#」以降に入れます（サーバー不要・サーバーに内容は届きません）。パスワードを付けると暗号化されます。リンクを知っている人は誰でも読めるため、未公開の企画にはパスワードを付けてください。取り込んだ画像はリンクに含まれません。また、`file://` で開いたページから作ったリンクは相手の環境で開けないため、GitHub Pages などに置いて使ってください。
