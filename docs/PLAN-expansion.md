# 拡張計画：ゲーム企画ノート v2

対象：`index.html`（HTML・CSS・JS を1ファイルに収録、ビルドなし、localStorage 保存）

## 0. 方針（全機能共通）

- **1ファイル・ビルドなし・サーバーなしを維持**する。外部ライブラリも追加しない（圧縮・暗号はブラウザー標準の `CompressionStream` / `crypto.subtle` を使う）。
- **既存データを壊さない**。保存キー `game-concept-note-v1` はそのまま、読み込み時に `normalize()` で新しい項目を補う（マイグレーション）。古いJSONバックアップも引き続き読み込める。
- **企画書本体（toMD）は1ページに収まる量を保つ**。検証日誌・ムードボード・ジャンル別回答などは「付録」扱いにし、書き出しやPDFで含めるかを選べるようにする。
- 既存のデザイン（方眼ノート・コバルト・マーカー、ダーク対応、狭幅で入力/プレビュー切替）に合わせる。

## 1. 基盤（フェーズ0）

| 変更 | 内容 |
|---|---|
| `blank()` に項目追加 | `team`（制作人数）、`period`（制作期間）、`genreTpl`（ジャンルテンプレートの種類）、`gq:{}`（ジャンル別質問の回答）、`mood:[]`、`playtests:[]` |
| `normalize(data)` 新設 | `blank()` を土台に、型が合う既存値だけを上書き。`load()`・インポート・共有リンクの読み込みで共通利用（既存の import 処理をこれに置き換え） |
| ドキュメントのメタ情報 | `store.docs[id]` に `parent`（複製元ID）、`variant`（版の名前）、`verdict`（採用/保留/不採用）、`reason`（採用理由）を追加。企画データ `data` とは分ける |
| フィールド型の追加 | `mood`、`playtests`、`gq` 用の描画関数を `fieldH()` に追加 |

## 2. 機能別の設計

### 2-1. 1ページPDF出力（小・先に着手）

- 「仕上げと書き出し」とプレビュー見出しに **「印刷・PDF保存」ボタン**。`renderPreview` を即時実行してから `window.print()`。
- `@media print`：トップバー・ステップ・フォーム・トースト等を非表示、`.sheet` だけを A4 1枚に。
  - `@page{size:A4;margin:12mm}`、本文 9.5pt 前後、h2 以降を **2段組（`column-count:2`）**、見出しと直後の段落を `break-after:avoid`。
  - ライト配色を強制（ダークモードでも白地で印刷）、`print-color-adjust:exact` でコンセプトのマーカー色を残す。
- 付録（検証日誌・ムードボード）は印刷ダイアログ前のチェックで「2ページ目以降に含める」を選べる。既定はオフ（1ページ優先）。
- 限界：フォント・余白はブラウザー依存なので「1ページに収まらない場合は縮小率を調整」のヒントを表示。

### 2-2. 企画の矛盾・スコープチェック（ルール式）

- 既存の `checks()`（記入漏れ）とは別に `review(s)` を新設し、仕上げ画面に **「見直したい点」** として別グループで表示（タグ：`見直し`）。断定ではなく**問いの形**で出す（例：「短時間で遊べることが狙いですが、1回が40分あります。区切りを作れますか？」）。
- 基本情報に **制作人数・制作期間** の入力欄を追加（任意）。
- 補助関数：`minutesOf(text)`（「10分」「1時間半」「1〜2時間」→分。範囲は最大値）、`hasAny(text, 語群)`。
- 初期ルール（各ルールは `{id, when(s), msg(s), step}` の配列で定義し、追加しやすくする）：

| # | 条件 | 出す問い |
|---|---|---|
| 1 | ターゲット/方針に「短時間・サクッと・スキマ・通勤」等があり、1回のプレイ時間が30分超 | 短時間が狙いなのに1回が長い |
| 2 | 方針の「N分を超えない」と、プレイ時間の1回の長さが食い違う | 自分で決めた上限と合っていない |
| 3 | 主要システム数＋動詞数が、制作人数×期間に対して多い（例：1人・3か月未満でシステム5つ以上） | 制作規模に対して要素が多い／どれを最初に削るか |
| 4 | 全体ボリュームが長い（例：20時間超）なのに1人・短期間 | コンテンツ量の見積もり |
| 5 | 楽しさに「物語」があるのに「今回は入れないもの」にストーリー系 | 物語が主役なのに削っている |
| 6 | 楽しさに「仲間」があるのに「今回は入れないもの」にマルチ/オンライン | 仲間の楽しさをどこで作るか |
| 7 | フックの種類が「物語」なのに楽しさに「物語」がない（同様に「見た目・音」と「感覚」） | フックと楽しさのずれ |
| 8 | プラットフォームがスマホなのに操作にスティック/トリガー/キーボード | 操作デバイスの不一致 |
| 9 | 「作りたくない体験」の語が、システム/ループにそのまま現れる（例：即死） | 避けたい体験を自分で入れていないか |
| 10 | ピラーの言葉がコアループ・システム・動詞に一つも現れない | その柱はループのどこで効くか |
| 11 | アイデア置き場が「今回は入れないもの」より大幅に多く、システムも多い | スコープが膨らんでいないか |
| 12 | プロトタイプの問いがあるのに、検証日誌に一度も記録がない／最新の結果が「未確認」 | 試したか |

- 語群（短時間・ストーリー・マルチ等）は定数にまとめ、誤検知しにくい語だけにする。誤検知時に消せるよう、項目ごとに「この指摘を非表示」を企画単位で保存（`dismissed:[]`）。

### 2-3. ジャンル別の質問テンプレート

- 基本情報に **「ジャンルの型」チップ**（単一選択）を追加：ローグライト／パズル／アドベンチャー・ノベル／アクション／RPG／シミュレーション・経営／ストラテジー／その他。
  - 「ジャンル」欄の文字から自動で候補を推定し、未選択なら「○○の質問を使いますか？」と提案（自動では確定しない）。
- `GENRE_TPL` 定数：ジャンル → ステップID → 質問の配列。例：
  - ローグライト：周回ごとに何が変わるか／死んだら何が残るか（メタ成長）／1回の運と実力の比率／ビルドの組み合わせは何から生まれるか
  - パズル：プレイヤーが発見するルールは何か／新しいルールをどの順で教えるか／「ひらめき」の瞬間はどこか／詰まったときの救済
  - ADV・ノベル：プレイヤーの選択は何を変えるか（結末/関係/情報）／物語と操作のどちらで感情を動かすか／周回・分岐の扱い
  - アクション：基本動作の気持ちよさ（入力→反応の速さ）／敵のパターンの読み合い／難易度の上げ方
  - RPG：成長の手ごたえ／戦闘以外で役割を表す方法／収集と物語のバランス
  - シミュレーション・経営：最適化したくなる数値は何か／放置と介入のバランス／失敗の回復
  - ストラテジー：判断の材料（情報の公開度）／1手の重み／勝ち筋の数
- 各ステップのフォーム下部に **「○○ならではの問い」** ブロックとして表示し、回答は `gq[質問ID]` に保存（ジャンルを変えても回答は消さない）。
- 記入率には含めない（任意の深掘り扱い）。企画書には「ジャンル別の深掘り」節として回答があるものだけ出力。AI相談文にも含める。

### 2-4. プロトタイプ検証日誌

- 「次に作るもの」と「仕上げ」の間に **ステップ「検証日誌」** を追加（11ステップになる）。
- 1件 = `{date, build, question, result, status, reaction, change}`
  - `question`：「確かめたい問い」。既定で現在の `question` をコピーして作成（後から企画の問いが変わっても記録は残る）
  - `status`：確認できた／一部／確認できなかった／未確認（チップ）
  - `result`：試作品での結果、`reaction`：プレイヤーの反応（誰が・何をした・何と言った）、`change`：次に変えること
- 「次に変えること」から **「未決定事項」「次に作るもの」へ送る** ボタン（コピーして追加）で改善サイクルにつなげる。
- 日付の新しい順に表示。プレビュー・Markdownでは「付録：検証日誌」として本文の後ろに出す（PDFは選択時のみ）。

### 2-5. ムードボード

- 「世界観・雰囲気」ステップに **ムードボード欄** を追加（既存の「参考作品・資料」はテキストの参考として残す）。
- 1件 = `{kind, url, title, note}`、`kind` は URL から自動判定：
  - 画像（拡張子 png/jpg/gif/webp など）→ サムネイル表示
  - YouTube / SoundCloud / Spotify / Bandcamp → 「音楽・動画」アイコン＋リンク
  - その他 → リンク
- `note` は **「何を参考にしたいか」**（色、空気感、テンポ…）。空なら仕上げチェックで「意図が書かれていない参考があります」と出す。
- 画像はURL参照のみを基本とする（理由：localStorage の容量・共有リンクの長さ）。※ ローカル画像の取り込みは下の「確認事項」参照。
- 外部画像は `referrerpolicy="no-referrer"`・`loading="lazy"`、読み込み失敗時はリンク表示にフォールバック。URLは `http(s):` のみ許可（`javascript:` 等を排除）。
- 企画書プレビュー/PDFではサムネイルのグリッド＋メモ、Markdownでは `- [タイトル](URL)：メモ`。

### 2-6. 企画の分岐・比較

- トップバーに **「複製して別案を作る」**。版の名前（例：「戦闘中心版」）を入力 → `parent` に元IDを入れて複製。企画セレクトでは `タイトル ／ 版の名前` で表示し、同じ系統をまとめる。
- トップバーに **「比較」** を追加 → 比較画面（フォームとプレビューの代わりに全幅表示）：
  - 左右で企画を2つ選ぶ（既定：現在の企画と、その親または兄弟）
  - 比較する行：一言コンセプト／フック／プレイヤーは何者か／楽しさの種類／ピラー／コアループ／1回のプレイ時間／主要システム／今回入れないもの
  - **違う行に印**、楽しさ・ピラー・動詞などの集合は「共通／片方だけ」を色分け。狭い画面では縦積み。
  - 各案に **判定（採用／保留／不採用）と採用理由** を記入（`verdict`, `reason` をドキュメントのメタに保存）。
- 採用理由は企画書の末尾に「この案を選んだ理由」として出力（記入時のみ）。

### 2-7. 読み取り専用の共有リンク

- 仕上げ画面に **「共有リンクを作る」**。
- 形式：`index.html#v=1.<base64url(deflate-raw(JSON))>`。**URLの `#` 以降はサーバーに送られない**ので、静的ホスティングでも内容がアクセスログに残らない。
- 開いたとき `#v=` があれば **閲覧モード**：入力UI・企画切替を出さず、企画書（＋任意でムードボード・検証日誌）だけを表示。上部に「自分のノートに取り込む」（normalize して新しい企画として追加）と「閉じる」。
- 含める範囲をチェックで選ぶ：未決定事項・アイデア置き場／検証日誌／ムードボード（既定：検証日誌オフ）。
- **長さの表示と警告**：生成後の文字数を表示し、2,000字超で「一部のチャットやSNSで切れる可能性」、8,000字超で「ファイル（JSON）での共有を推奨」。
- **未公開企画の注意**：リンクを知っている人は誰でも読めること、チャット履歴・ブラウザー履歴に残ること、取り消しできないことを生成ボタンの近くに明記。
- 任意で **パスワード保護**（`crypto.subtle` の PBKDF2 → AES-GCM。`#v=1e.<salt>.<iv>.<cipher>`）。閲覧時にパスワード入力欄を表示。
- `CompressionStream` 非対応ブラウザーでは非圧縮で生成（長くなる旨を表示）。
- 注意：`file://` で開いている場合、リンクは相手の環境で開けないため、「GitHub Pages 等に置いた URL で共有してください」と案内（`location.protocol==='file:'` を検出）。

## 5. 検証方法

テスト基盤がないため、Playwright（環境にプリインストール済み）で各フェーズ後に確認：

- 既存の localStorage データ（v1形式）を入れた状態で開き、エラーなく表示・新項目が補われること
- 各チェックルールが、該当する入力で出て、外すと消えること（ルールごとに最小ケース）
- 印刷プレビュー（`page.pdf()`）で記入例が A4 1ページに収まること、ダーク設定でも白地であること
- 共有リンク：生成→新しいページで開く→閲覧モードで同じ内容→取り込み、の往復。パスワード有無の両方
- 複製→比較画面で差分表示・採用理由の保存
- 幅 375px でレイアウト崩れ・横スクロールがないこと（ライト/ダーク）

## 6. 確認したいこと（#2 で決定済み）

決定：1=B（ローカル画像も縮小して取り込む。共有リンクには含めない）、2=A（パスワード保護を任意機能として入れる）、3=A（7種類＋その他）、4=A（全フェーズを実装）。

実装時の変更：印刷は2段組では記入例が1ページに収まらなかったため、3段組・8pt前後にした。

1. ~~**ムードボードの画像**~~：URL参照のみでよいか。ローカル画像も取り込む場合は縮小して保存（1枚40KB程度）になり、共有リンクには含められません。
2. **共有リンクのパスワード保護**：入れるか（推奨：任意機能として入れる）。
3. **ジャンルの型**：上の7種類＋その他で足りるか（例：リズム、ホラー、カード、サバイバルなどを追加するか）。
4. **実装範囲**：全フェーズを一度に進めるか、フェーズ0〜2（基盤・PDF・チェック）で一度確認を挟むか。
